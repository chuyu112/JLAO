JLAO 视频号直播 AI 运营大脑 PRD日期：2026-05-24版本：v0.2状态：新版方向整理稿项目简称：JLAO项目全称：Jade Live AI Optimizer中文定位：任意直播间可演示的 AI 运营大脑第一版 MVP demo 截止日期：2026-05-31（5.31 完成）第二版全功能截止日期：2026-06-301. 产品一句话JLAO 是一个面向视频号和任意直播间的 AI 运营大脑。它通过图像识别、语音识别、直播间知识库、客户记忆数据库和多 Agent 协作，帮助直播团队理解现场内容、模拟客户互动、自动生成低风险场控话术，并通过 scrcpy 在真实直播间完成低风险发言演示。其中，知识库和数据库是 JLAO 的两条长期资产主线：```text知识库负责沉淀“直播间知道什么”数据库负责沉淀“客户和直播发生过什么”```没有知识库，Agent 只能临场胡说；没有数据库，系统无法形成客户记忆、评级和复盘增长。2. 核心原则```text原有功能保留不变第一版 MVP demo 可在任意直播间演示不依赖视频号后台接口客户系统第一版使用虚拟客户池多 Agent 第一版使用虚拟角色和部分真实发言低风险话术可自动发送高风险话术必须人工确认所有自动行为必须可暂停、可追踪、可复盘```3. 背景与机会原 JLAO 已经具备直播转写、手机投屏、手机截图、商品识别、AI 建议、风控提醒和复盘能力。下一阶段不再只做“主播和场控建议工具”，而是升级为一个完整的直播运营系统。直播间实际运营中，团队面对的问题包括：主播讲解内容变化快，场控难以及时抓住锚点。客户进房、提问、停留、购买意向分散，人工很难形成长期记忆。新场控缺少话术经验，直播间气氛容易断。老客和高价值客户没有被及时识别和承接。直播知识沉淀在个人经验、文档、聊天记录里，不能实时参与决策。平台规则、违禁词、售后承诺、隐私边界容易被忽略。直播结束后的公众号、短视频、货架电商内容需要重复整理。JLAO 的新版机会是把直播现场感知、客户资产、知识库和多 Agent 运营串成一个闭环。新版 JLAO 的长期价值不只是实时提词，而是沉淀两类资产：知识资产：商品知识、平台规则、直播话术、客服 FAQ、历史复盘、Agent 人设。数据资产：客户档案、客户发言、客户提问、购买记录、偏好标签、直播表现、Agent 发言效果。4. 第一版 MVP demo 定位4.1 第一版 MVP demo 目标第一版 MVP demo 要在 5.31 完成，做成一个能在任意直播间现场演示的外挂式 Demo。```text任意直播间画面+ 主播或直播间声音转文字+ 手机截图和图像识别+ C:\Users\chuyu\Desktop\wiki.md 知识库+ 虚拟客户池+ 多 Agent 运营= JLAO 内模拟客户互动和 Agent 协作+ 低风险 Agent 话术通过 scrcpy 真实发到直播间+ 直播后生成复盘和内容草稿包```第一版 MVP demo 要证明：系统能听懂主播正在讲什么。系统能看懂当前直播画面和商品状态。系统能读取本地 Wiki 知识。系统能模拟不同等级、偏好和性格的客户。系统能让多个 Agent 基于同一上下文协作。系统能自动生成低风险直播间发言。系统能通过 scrcpy 把低风险话术发到真实直播间评论区。系统能把直播过程沉淀成复盘和内容草稿。4.2 第一版 MVP demo 不做什么第一版明确不做：不接视频号后台接口。不真实锁定某个直播间。不抓取真实客户列表。不抓取真实粉丝实名。不定位真实粉丝到市区级。不做真实订单、物流、售后闭环。不做真实企微导流自动化。不做竞争店铺大规模抓取。不做全自动高风险促单。不做平台规则的完整自动化解析。这些能力作为后续阶段。5. 核心用户5.1 一线使用者主播场控客服直播运营5.2 管理使用者直播间负责人商家老板培训负责人内容负责人5.3 第一版 MVP demo 主要使用者第一版优先服务“演示者”和“运营场控”：```text一个人打开 JLAO接入任意直播间画面和声音启动虚拟客户池和多 Agent观察系统如何自动识别上下文、模拟客户、生成话术、真实发言```6. 总体架构```text感知层  -
