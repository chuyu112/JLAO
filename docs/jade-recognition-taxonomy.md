# 翡翠识别分类说明

本文档定义 JLAO 当前翡翠识别、人工标注、反馈学习和 YOLO 训练使用的分类口径。

## 总原则

1. 前端和后端统一使用“款式”，不再使用“样式”作为显示文案。
2. `style` 表示货品的基础形态，例如手镯、珠串、吊坠。
3. `theme` 表示雕刻或造型题材，例如观音、平安扣、龙牌。
4. `craft` 表示工艺状态，目前只区分裸石和镶嵌。
5. 牌子、挂件、平安扣、龙牌、山水牌、无事牌等不再作为独立款式输出，业务属性上统一归到 `style=吊坠`，题材放到 `theme`。

## 业务分类层级

不看 YOLO 训练标签时，先按业务分类理解：

```text
翡翠货品
├─ 手镯
├─ 珠串
├─ 珠链
├─ 蛋面
├─ 戒指
├─ 吊坠/挂坠
│  ├─ 观音
│  ├─ 佛公
│  ├─ 平安扣
│  ├─ 如意
│  ├─ 叶子
│  ├─ 山水
│  ├─ 貔貅
│  ├─ 葫芦
│  ├─ 无事牌
│  ├─ 财神
│  ├─ 龙牌
│  ├─ 福瓜
│  └─ 福豆
├─ 耳饰
└─ 摆件
```

所以：

- 佛公不是业务大类，应归为 `style=吊坠, theme=佛公`。
- 观音不是业务大类，应归为 `style=吊坠, theme=观音`。
- 平安扣不是业务大类，应归为 `style=吊坠, theme=平安扣`。
- 龙牌、山水牌、无事牌也不是业务大类，应归为 `style=吊坠`，再分别写入对应 `theme`。

### 颜色 color

当前标准取值：

```text
帝王绿 / 阳绿 / 辣绿 / 苹果绿 / 豆绿 / 绿色 / 蓝水 / 晴水 / 油青 / 紫罗兰 / 春带彩 / 白冰 / 无色 / 白底青 / 飘花 / 洒金 / 黄翡 / 冰黄 / 墨翠 / 红翡 / 多彩
```

### 种水 water

当前标准取值：

```text
玻璃种 / 高冰 / 冰种 / 冰胶 / 起冰 / 糯冰 / 起胶 / 糯化 / 糯种 / 豆种
```

前期 `糯冰` 和 `冰糯` 合并为一个标签，统一输出 `糯冰`。行业里两者经常混用，前期强行拆分会降低标注效率和一致性。

前期 `细糯`、`细糯种`、`糯化`、`糯化种` 合并为一个标签，统一输出 `糯化`。两者不是严格同义，但在直播识别和人工标注阶段高度同质化，先合并可以减少争议样本。

归一规则：

| 原始说法 | 标准种水 |
|---|---|
| 冰糯、冰糯种 | 糯冰 |
| 糯冰、糯冰种 | 糯冰 |
| 细糯、细糯种 | 糯化 |
| 糯化、糯化种 | 糯化 |

## 标注数据用途分层

人工标注时会记录多种字段，但这些字段不是都给 YOLO 用。当前应分成两层：

```text
YOLO 用：定位主体 + 粗分类
未来储备用：细属性、题材、工艺、行业知识、VLM 训练/评估
```

## 前期最高效率分类策略

前期目标是尽快形成可用闭环：YOLO 稳定框主体，业务数据沉淀细属性，未来可以训练/评估 VLM。不要一开始把所有题材都拆成 YOLO 类。

推荐分成三层标注：

### 第一层：必须标，直接服务 YOLO

只要画面里有清晰翡翠主体，就优先完成这一层。

| 字段 | 要求 | 用途 |
|---|---|---|
| 主体框 `box` | 必填 | 训练 YOLO 定位 |
| 粗款式 `style` | 必填 | 映射 YOLO 粗类 |
| YOLO 类 `class_name` | 自动或人工确认 | 训练 YOLO 粗分类 |
| 是否负样本 | 必填 | 区分无主体、黑屏、非翡翠等样本 |

前期 YOLO 粗类建议控制在：

```text
手镯 / 珠串 / 珠链 / 蛋面 / 戒指 / 吊坠 / 耳饰 / 摆件
```

这 8 类效率最高：样本需求少、视觉差异明显、能覆盖直播间主要货形。

### 第二层：能判断就标，服务业务和未来 VLM

这些字段越细越好，但不能因为不确定就丢掉 YOLO 样本。

| 字段 | 前期做法 | 用途 |
|---|---|---|
| `theme` 题材 | 能判断就选，不能判断标记为待确认 | VLM 细识别训练/评估 |
| `craft` 工艺 | 能判断裸石/镶嵌就选 | 商品归档、讲货提示 |
| `color` 颜色 | 能判断就选，不能判断留待确认 | VLM/规则颜色校准 |
| `water` 种水 | 能判断就选，不能判断留待确认 | VLM/规则种水校准 |
| STT/OCR 文本 | 自动保存 | 与图片互证，训练多模态样本 |

重点：颜色、种水、题材不确定时，不应直接把整张图判为负样本。只要主体框清楚，这张图仍然可以进入 YOLO 训练。

### 第三层：低频题材先储备，不进 YOLO 细类

关公、大日如来、普贤菩萨、千手观音、西方三圣等题材，前期先作为 `theme` 保存。

```text
style=吊坠
theme=关公
yolo_class=jade_pendant
```

后期只有满足这些条件，才考虑把题材升级为 YOLO 独立类：

1. 样本数量足够多。
2. 视觉特征稳定。
3. 和其它题材经常混淆，VLM 单独识别不够稳定。
4. 业务上确实需要实时框级题材识别。

建议门槛：每个细题材至少几十到上百张高质量框标注图，再考虑单独建 YOLO 类。

### 前期推荐判断流程

```text
1. 图里有没有清晰翡翠主体？
   - 没有：负样本
   - 有：继续

2. 主体能不能框出来？
   - 不能：负样本或待复核
   - 能：画框

3. 粗款式是什么？
   - 手镯 / 珠串 / 珠链 / 蛋面 / 戒指 / 吊坠 / 耳饰 / 摆件

4. 能否判断细题材？
   - 能：写入 theme
   - 不能：theme 待确认，但样本仍可用于 YOLO

5. 能否判断颜色、种水、工艺？
   - 能：写入字段
   - 不能：字段待确认，不影响 YOLO 框训练
```

### 给 YOLO 的标注

YOLO 只需要这些字段：

| 字段 | 是否给 YOLO | 说明 |
|---|---|---|
| 图片 | 是 | 原始图或裁剪图，作为训练图片 |
| 主体框 `box` | 是 | YOLO 必须学习主体位置 |
| YOLO 类 `class_name` | 是 | 粗粒度检测类，例如 `jade_pendant`、`jade_bangle` |
| 负样本标记 | 间接使用 | 可用于筛掉不进正样本的数据，或后续构建背景/无目标样本 |

YOLO 前期目标：

```text
1. 画面里有没有翡翠主体
2. 主体在哪里
3. 主体大概是什么形态
```

YOLO 前期不负责：

```text
颜色
种水
细题材
工艺
价格
寓意
真假判断
```

示例：

```json
{
  "image": "samples/001.jpg",
  "box": {
    "class_name": "jade_pendant",
    "x_center": 0.52,
    "y_center": 0.43,
    "width": 0.34,
    "height": 0.46
  }
}
```

### 给未来储备的标注

这些字段不直接作为 YOLO 类别，但必须保存下来，后续用于 VLM 微调、提示词优化、规则学习、商品库沉淀和质检评估。

| 字段 | 是否给 YOLO | 未来用途 |
|---|---|---|
| `color` 颜色 | 否 | VLM/分类器识别颜色，校准颜色规则 |
| `water` 种水 | 否 | VLM/分类器识别种水，沉淀行业判断样本 |
| `style` 款式 | 间接 | 可映射到 YOLO 粗类，也用于业务展示 |
| `theme` 题材 | 否，前期不直接给 YOLO | VLM 细识别，例如关公、大日如来、普贤、千手观音 |
| `craft` 工艺 | 否 | 区分裸石、镶嵌，辅助讲货和商品归档 |
| 讲解文本 / OCR 文本 | 否 | STT/OCR 与图片互相校验，训练多模态样本 |
| 置信度 / 纠错来源 | 否 | 分析模型错因，做反馈学习和评估 |
| 负样本原因 | 否 | 清洗数据、排查误采集、训练无效样本判定 |

示例：

```json
{
  "image": "samples/001.jpg",
  "yolo_class": "jade_pendant",
  "box": [0.52, 0.43, 0.34, 0.46],
  "color": "黄翡",
  "water": "糯冰",
  "style": "吊坠",
  "theme": "关公",
  "craft": "裸石",
  "text": "这件是黄翡关公，糯冰，裸石未镶嵌。"
}
```

这条数据对 YOLO 来说是：

```text
图片 + 框 + jade_pendant
```

对未来 VLM 来说是：

```text
裁剪图 + 文本 + 标准答案：黄翡 / 糯冰 / 吊坠 / 关公 / 裸石
```

### 当前推荐策略

1. YOLO 类保持粗，不要一开始把所有题材都做成检测类。
2. 标注工具可以细，把题材和工艺尽量记录完整。
3. 高频、视觉特征稳定、样本量足够的题材，后期再升级成 YOLO 类。
4. 低频题材只作为 `theme` 储备，不影响当前 YOLO 稳定性。
5. 每条标注数据同时服务两个目标：当前训练 YOLO，未来训练/评估 VLM。

## 标注口径

1. 有主体翡翠时，必须选颜色、种水、款式、工艺，并框出主体。
2. 款式为吊坠时，必须选择题材；无法判断题材时，不要强行标为具体题材类，应按无可标注原因处理或保留基础吊坠类。
3. 图里没有翡翠、主体太小、严重遮挡、黑屏花屏、非翡翠商品、无法确定主商品等情况，进入负样本，不进入翡翠框训练集。
4. `craft` 不参与 YOLO 类别编号，只作为识别属性和训练反馈字段保存。
5. `jade_plaque` 是历史检测类，训练集可继续兼容；业务属性展示时仍应输出 `style=吊坠, theme=无事牌` 或对应牌类题材。
