# 视频号翡翠直播观察沙盘 MVP 设计

## 结论

JLAO 当前阶段值得继续做，但不应以“自有直播间运营大脑”作为第一验证目标。因为自有直播间还没成立，无法马上验证老客承接、店长复盘省时、成交提升等经营指标。

当前 MVP 应收缩为：

**视频号翡翠直播观察 + 虚拟场控回复 + 训练样本生成器。**

## 使用场景

用户用手机打开公开视频号翡翠直播，把手机投屏到电脑。JLAO 采集投屏画面和声音，分析公开直播内容，并在控制台生成观察事件、虚拟回复和训练素材。

系统只做平台外模拟，不向视频号发送任何真实评论、私信或互动。

## 目标用户

当前目标用户是未来直播团队的店长、运营和新人主播。第一阶段不服务外部客户，也不承诺提升成交。

## 核心假设

1. 公开视频号翡翠直播足够多，可以作为早期训练和功能测试样本。
2. 手机投屏到电脑的采集链路可以稳定获得画面、声音或字幕。
3. 即使不能接入真实评论数据，系统也能从主播话术和画面中生成有学习价值的观察。
4. 虚拟回复能帮助团队训练场控和主播反应，但不能真实发送到平台。

## MVP 闭环

```text
手机打开视频号翡翠直播
-> 投屏到电脑
-> JLAO 采集画面/声音/字幕
-> 转写主播话术
-> 识别商品讲解、风险话术、客户问题线索
-> 生成虚拟场控回复
-> 生成观察报告
-> 沉淀新人训练样本
```

## 功能范围

### 必须做

- 投屏画面采集。
- 直播话术转写或手动转写导入。
- 商品讲解维度识别：种水、颜色、瑕疵、尺寸、证书、价格。
- 风险话术识别：绝对化、保真、升值、最低价、夸大承诺。
- 虚拟场控回复流：只在 JLAO 控制台展示，不发送。
- 观察报告：总结同行直播打法、可学习话术、风险样本。
- 新人训练素材：优秀话术、反面案例、训练题。

### 暂不做

- 真实自动回复视频号。
- 真实客户画像和老客记忆。
- 成交提升归因。
- 店长复盘省时指标。
- 自有直播团队管理。

## 虚拟回复类型

1. 主播补充话术  
   当主播漏讲证书、瑕疵、自然光、尺寸等信息时，生成可补充的话术。

2. 用户问题模拟回复  
   当转写中出现价格、瑕疵、证书、上手效果等问题线索时，生成“如果这是我们的直播间，可以这样回复”的话术。

3. 风险改写回复  
   当主播出现高风险表达时，生成安全改写。

所有虚拟回复必须显示：

```text
仅模拟，不发送
仅供训练，不代表平台真实互动
```

## 观察报告结构

1. 直播间基本观察
2. 商品讲解结构
3. 主播话术样本
4. 用户问题线索
5. 风险话术与改写
6. 新人训练素材

## 成功标准

先测试 5 场公开视频号翡翠直播。只要满足下面 3 条，就值得继续：

- 手机投屏采集链路能稳定跑满 20 分钟。
- 每场能产出 5 条以上可用观察事件。
- 每场能产出 3 条以上可训练话术。
- 风险话术识别至少能抓住明显违规表达。
- 虚拟回复让人感觉“像场控会说的话”，而不是泛泛 AI 文案。

## 下一步任务

1. 把现有“多 Agent 发言流”产品文案改成“虚拟场控回复流”。
2. 把复盘报告在 MVP 中改成“观察报告”。
3. 弱化老客、客户记忆和真实自动回复。
4. 强化投屏采集、话术转写、风险改写和训练样本。
