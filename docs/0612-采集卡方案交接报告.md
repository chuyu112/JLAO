# 0612 采集卡方案交接报告

日期：2026-06-12

## 当前硬件变化

用户已从 Android 手机 + scrcpy/ADB 方案，切换到苹果手机采集卡方案：

- 手机：iPhone 13 Pro Max
- 视频链路：iPhone -> Lightning 转 HDMI -> HDMI 采集卡 -> USB3.0 -> PC
- 目标：不使用 OBS，不让客户操作外部工具，直接融合进 JLAO

这个链路不再依赖：

- ADB
- scrcpy
- Android playback 音频采集
- 浏览器选择 scrcpy 窗口

## 新方案结论

新增一个独立的「HDMI 采集卡模式」，不要继续把它套进 Android/scrcpy 模式。

推荐架构：

```text
iPhone
  -> Lightning HDMI
  -> HDMI 采集卡
  -> JLAO 后端统一打开视频/音频设备
  -> 前端预览 / STT / OCR / YOLO / 录屏
```

核心原则：

- 采集卡视频和音频由后端统一接管。
- 前端只显示后端推送出来的画面，不再通过浏览器 `getDisplayMedia` 选择窗口。
- STT、OCR、YOLO、录屏都共享后端同一份采集卡输入。
- 不让浏览器、后端、OBS、录屏模块分别抢同一个采集卡设备。

## 建议的前端按钮逻辑

采集卡模式下建议拆成这些独立开关：

- 采集卡输入：打开/关闭采集卡视频 + 音频底层输入
- 语音识别：启动/停止 STT
- OCR 识别：启动/停止 OCR
- YOLO 检测：启动/停止 YOLO
- 录屏：启动/停止录屏
- 声音监听：是否把采集卡声音播放到电脑音箱

依赖关系：

- 未打开「采集卡输入」时，STT/OCR/YOLO/录屏不能启动。
- 如果用户点击依赖功能，要明确报错：采集卡未接入，无法启动。

## 设置项建议

设置里新增：

- 输入模式：Android scrcpy / HDMI 采集卡
- 视频设备：选择采集卡视频设备
- 音频设备：选择采集卡音频设备
- 预览帧率：默认 30fps
- OCR 频率：默认 1 秒一次
- YOLO 频率：可选
- STT provider：本地 FunASR / 阿里云
- 声音监听：开/关
- 硬重置：释放所有输入、关闭后台进程、清状态

## 状态设计

每个模块都要显示清楚状态：

- 未启动
- 初始化中
- 运行中
- 停止中
- 失败
- 设备断开

USB 或采集卡断开时：

1. 自动重连一次。
2. 重连失败后停止底层采集。
3. STT/OCR/YOLO/录屏全部进入断开或停止状态。
4. 前端显示明确错误，不假装还在运行。

## 实施顺序

重启后建议从最小验证开始，不直接改完整链路：

1. 后端增加采集卡设备检测接口，列出视频设备和音频设备。
2. 前端设置页展示可选视频设备、音频设备。
3. 后端独占打开采集卡视频，前端稳定看到画面。
4. 接入采集卡音频到阿里云 STT。
5. OCR 从同一份视频流抽帧。
6. YOLO 从同一份视频流抽帧。
7. 录屏用同一份视频 + 音频保存 mp4。
8. 最后整理 UI 按钮、状态、错误提示。

## 重启后第一步

先不要接 STT/OCR/录屏。

第一步只做：

```text
采集卡设备枚举
```

目标是确认 Windows 能看到：

- 采集卡视频设备
- 采集卡音频设备

只有设备枚举稳定后，再进入「打开视频预览」。
