# 采集控制与资源状态设计

本文档记录当前讨论确认的目标方案。后续代码改动应按本文逐条实现，不再把投屏、视频流、音频、STT、OCR、录屏互相隐式绑定。

## 目标

- PC-B 和 PC-C 使用同一套逻辑，差异通过配置和环境处理，不做机器专属分支。
- 每个功能入口只控制自己的资源，状态可见、可查、可重置。
- 前后端重启后不继承旧的假状态，必须回到新的真实状态。
- 任何依赖不满足时明确报错，并打印后端日志。
- 视频区域显示真实视频流，不使用 ADB 截图冒充视频流。
- ADB 截图只用于截图、OCR、样本保存等分析任务。

## 主操作 Toggle

主操作区使用 6 个独立 Toggle，按钮风格一致，每个按钮带图标和颜色。

| Toggle | 建议图标/颜色 | 控制资源 | 职责 |
| --- | --- | --- | --- |
| 采集 | 绿色连接器 | `scrcpy_projection` | 启动/停止后端会话和 scrcpy 投屏 |
| 接入视频流 | 蓝色连接器/投屏 | `browser_video_stream` | 浏览器选择并接入 scrcpy 窗口视频流 |
| 音频接入 | 声波/耳机 | `native_audio_stream` | 接入手机 playback 音频流 |
| 语音识别 | 麦克风 | `native_stt` | 消费音频流做 STT |
| 截图/OCR | 取景框/扫描 | `ocr_capture` | 消费视频流截图做 OCR/样本 |
| 录屏 | 红色录像键 | `recorder` | 消费视频流和音频流生成录屏 |

交互规则：

- Toggle 未开启时低亮灰色。
- Toggle 开启时使用对应颜色点亮。
- 点击一次启动，再点一次停止。
- 不再额外放一个全局红色停止按钮。
- 停止按钮不要使用强红色，录屏运行态可以使用明显红色。

## 资源模型

后端和前端应围绕 6 个资源建模：

- `scrcpy_projection`：只管 scrcpy 投屏窗口。
- `browser_video_stream`：前端 MediaStream 状态，后端只接收已接入/已断开的状态。
- `native_audio_stream`：手机 playback 音频接入。
- `native_stt`：只消费 `native_audio_stream`。
- `ocr_capture`：只消费 `browser_video_stream` 的截图帧。
- `recorder`：消费 `browser_video_stream` 的视频帧和 `native_audio_stream` 的音频帧。

每个资源至少应有这些状态：

- `stopped`
- `starting`
- `running`
- `stopping`
- `error`

不能只靠按钮亮不亮判断真实状态。

## 依赖关系

| 功能 | 前置条件 | 前置不满足时 |
| --- | --- | --- |
| 采集 | ADB 设备在线 | 报错，不启动 |
| 接入视频流 | 已有 scrcpy 投屏窗口 | 报错，Toggle 回到关闭 |
| 音频接入 | ADB 设备在线且手机支持 playback 音频采集 | 报错，Toggle 回到关闭 |
| 语音识别 | 音频接入已运行 | 报错“请先打开音频接入” |
| 截图/OCR | 视频流已接入 | 报错“请先接入视频流” |
| 录屏 | 视频流已接入，音频接入已运行 | 报错说明缺视频还是缺音频 |

约束：

- 不自动偷偷开启别的功能。
- 一个功能停止时只停止自己。
- 如果底层资源正被其他功能使用，不允许关闭，并说明原因。
- 例如 STT 或录屏正在运行时，不允许关闭音频接入。

## 采集语义

`采集`只做两件事：

- 启动后端会话。
- 启动 scrcpy 投屏。

`采集`不做这些事：

- 不启动 STT。
- 不启动 OCR。
- 不自动接入浏览器视频流。
- 不启动录屏。
- 不自动接入音频。

如果关闭`采集`时还有依赖投屏的资源在运行，应阻止关闭并提示先停止相关功能。

## 视频流语义

`接入视频流`表示浏览器接入 scrcpy 投屏窗口的真实视频流。

- 视频显示应来自真实视频流，不是 ADB 截图轮询。
- ADB 截图频率不能被当作视频帧率使用。
- 视频流卡死应由帧时间判断，例如超过 3 秒没有新帧则判定异常。
- 视频流断开时，`接入视频流`必须自动回到关闭或错误状态。
- OCR 和录屏依赖视频流，视频流断开时应同步停止或异常结束。

## 音频语义

`音频接入`表示接入手机 playback 音频流。

- 音频源固定为手机播放音 `playback`。
- 不是手机麦克风。
- 不是电脑麦克风。
- 不要求 PC 扬声器能听到声音。
- STT 和录屏复用同一条音频通道。

如果音频通道断开：

- `音频接入`自动变为关闭或错误。
- `语音识别`自动停止并报错。
- `录屏`自动停止，保留临时文件，并尝试合成。

## 语音识别

`语音识别`只负责启动/停止 STT。

- 必须先打开`音频接入`。
- 只消费已有的 `native_audio_stream`。
- 不负责启动或停止音频接入。
- STT 卡住时只重置 STT，不重置全部系统。
- STT 异常要打印明确后端日志。

FunASR 配置按 PC-C 成功配置对齐，GPU/CPU 作为设置项处理，不能写死影响另一台机器。

## 截图/OCR

`截图/OCR`只负责截图、OCR、样本保存等分析任务。

- 必须先接入视频流。
- 截图频率和 OCR 频率做成配置项。
- 默认可以按 1 秒一次处理。
- 视频显示帧率和截图/OCR频率必须分开。
- 开启 OCR 不应影响 STT 音频链路。

## 录屏

`录屏`必须带声音。

录屏源：

- 视频：来自已接入的视频流。
- 音频：来自手机 playback 音频接入。

建议实现：

- 录屏时分别保存临时视频文件和临时音频文件。
- 停止录屏时使用工具合成最终 `mp4`。
- 合成失败时保留临时视频文件和音频文件，并明确报错。

约束：

- 录屏不应挂在`采集`里。
- 只有点击`录屏`才开始录。
- 录屏停止只停止 recorder 自己。
- 录屏要求视频流和音频接入都已运行。
- 录屏过程中任一底层流断开时，录屏异常停止，保留临时文件。

## 异常断开处理

异常必须让状态回到真实状态，不能让 Toggle 假亮。

处理原则：

- USB 断开、ADB offline、手机临时断连属于设备链路小故障，可以自动重连 1 次。
- 自动重连只恢复“设备可用”判断，不自动恢复 STT、OCR、录屏、视频流等业务功能。
- 前端死机、后端死机、电脑异常、业务进程卡死、状态错乱，不算小故障，不能偷偷硬重置后继续假装正常。
- 业务功能异常时先停止受影响资源、同步状态、报错、打印日志，再让用户决定是否手动软重置或硬重置。
- 任何异常都不能让按钮继续假亮，UI 必须以 `/status` 返回的真实资源状态为准。

| 异常 | 处理 |
| --- | --- |
| 手机 USB 断开 / ADB offline | 设备状态变断开，自动尝试重连 1 次 |
| USB 自动重连成功 | 只恢复设备可用状态，不自动恢复功能 |
| USB 自动重连失败 | 保持设备断开，提示检查线和授权 |
| scrcpy 投屏进程退出 | `采集`自动关闭或进入错误，提示投屏已断开 |
| 浏览器视频 track ended | `接入视频流`自动关闭 |
| 视频流卡死 | 关闭视频流状态，停止依赖的视频任务 |
| 音频流断开或卡死 | 关闭音频接入，停止 STT/录屏 |
| STT 卡住 | 只重置 STT |
| OCR 卡住 | 只重置 OCR |
| 录屏异常 | 停止录屏，保留临时文件，尝试合成 |
| 后端进程重启 | 清空内存资源状态，杀本项目残留进程，不自动启动任何功能 |
| 前端刷新或崩溃恢复 | 丢弃本地 Toggle 状态，重新从后端 `/status` 同步 |
| 电脑休眠/卡死恢复 | 全部资源状态重新校验，无法确认的资源统一置为 `error` 或 `stopped` |

默认不对业务功能异常做自动硬重置。先报错、同步状态、允许用户手动重置。

## 前后端重启策略

前端刷新、前端重启、后端重启后，都不能继承旧状态。

后端启动时执行启动重置：

- 清空后端内存状态。
- STT、OCR、录屏、视频流、音频流、会话全部置为 `stopped`。
- 停掉旧后台任务、队列、计时器。
- 清理本项目启动的残留 scrcpy/音频进程。
- 清理本项目写入的资源锁、会话锁、临时运行态标记。
- 检查 ADB 设备状态。
- 对 `offline` 设备自动 `adb reconnect offline` 一次。
- 不自动开启任何功能。
- 不删除录屏临时文件、样本、日志。

启动清理边界：

- 只清理本项目明确启动或明确标记的进程，避免误杀用户手动打开的其他工具。
- 如果无法判断某个外部进程是否属于本项目，只记录日志和状态告警，不直接杀。
- 启动重置后所有 Toggle 默认关闭，即使旧进程还在，也不能显示为运行中。
- 若检测到旧 scrcpy 窗口仍存在但不归本项目管理，`采集`启动时应提示冲突或要求用户关闭，而不是直接复用未知窗口。

前端启动或刷新时：

- 不从 localStorage 恢复开关开启状态。
- 页面加载后先显示关闭或同步中。
- 请求后端当前真实 `/status`。
- WebSocket 断开重连后重新拉 `/status` 覆盖前端状态。
- 后端状态未知时显示“状态未知，请重置”，不能继续假亮。
- 前端保存的设置项可以保留，例如 FunASR CPU/GPU、OCR 间隔，但运行态开关不能保留。

## 重置机制

设置里提供重置入口，不放在主操作区。

重置不是常规错误处理的替代品。普通启动失败必须先给出具体错误；只有状态已经乱掉、进程卡死、ADB 卡死、前后端无法确认真实状态时，才使用重置入口。

### 软重置

用于软件状态错乱：

- 停 STT。
- 停 OCR。
- 停录屏并保留临时文件。
- 停音频接入。
- 停视频流状态。
- 停后端会话。
- UI 所有 Toggle 回到关闭。
- 清理前后端内存状态、队列、缓存、计时器。
- 不杀 ADB。
- 不删除录屏临时文件、样本、日志。
- 适用于 STT/OCR/录屏/视频流/音频流状态错乱，但 ADB 本身仍可用的情况。

### 硬重置

用于调试、ADB、scrcpy、USB 卡死：

- 先执行软重置。
- 杀本项目启动的 `scrcpy` 和音频进程。
- 执行 `adb reconnect offline`。
- 必要时可选 `adb kill-server`。
- 重新检测设备。
- UI 所有 Toggle 回到关闭。
- 不自动启动任何功能。
- 不删除录屏临时文件、样本、日志。
- 适用于 USB 卡死、ADB offline 长时间不恢复、scrcpy 残留进程干扰、音频采集进程无法退出的情况。

UI 规则：

- `硬重置`放在设置里。
- 使用警示但不要强红的样式，例如橙色描边。
- 点击后需要二次确认。
- 硬重置执行结果必须显示清楚：清了哪些进程、ADB 是否在线、当前设备状态是什么。

## 日志要求

后端日志不能隐藏。每次状态变化都应打印：

- 哪个资源开始启动。
- 哪个资源启动成功。
- 哪个资源启动失败和失败原因。
- 哪个资源被用户停止。
- 哪个资源异常断开。
- 异常影响了哪些依赖功能。
- 重置执行了哪些清理动作。

前端错误提示应和后端日志对应，不能只显示泛化失败。

## 后续实现顺序建议

1. 状态模型和 `/status` 同步。
2. 启动重置、软重置、硬重置。
3. 6 个 Toggle UI 和前置检查。
4. 拆分采集、视频流、音频接入、STT、OCR、录屏。
5. 异常断开和心跳检测。
6. 录屏音视频分离保存与合成。
7. 配置项：FunASR CPU/GPU、截图/OCR频率、视频流检测阈值。
