# JLAO 1.0 产品需求文档

版本：1.0  
产品名称：JLAO（Jade Live AI Optimizer，翡翠直播 AI 优化器）  
文档日期：2026-06-13  
当前阶段：内部 MVP / 1.0 可演示版本  

## 1. 产品定位

JLAO 1.0 是面向翡翠直播团队的直播观察、数据挖掘和运营辅助系统。当前版本优先服务“其它直播间分析”和内部训练，不直接接管平台互动，不向视频号、抖音或其它平台自动发送评论、私信、下单等动作。

1.0 的核心定位是：

- 通过采集卡或手机投屏采集公开翡翠直播间的视频和音频。
- 对直播画面、主播语音、截图 OCR、翡翠图像特征、直播弹幕/线索进行结构化分析。
- 沉淀商品讲解、风险话术、客户问题、虚拟场控回复、截图证据和复盘材料。
- 为后续翡翠专有模型、专有知识库、运营脚本和数据复盘体系积累样本。

## 2. 背景与问题

翡翠直播高度依赖主播经验、场控配合和商品知识。早期团队缺少稳定自有直播间，因此 1.0 不先做“自动运营自有直播间”，而是先从公开直播观察切入：

- 公开翡翠直播间足够多，可以低成本积累话术、画面和商品样本。
- 通过对同行直播间的持续观察，可以训练新人主播和场控。
- 直播画面、语音、弹幕、成交卡片、商品描述都可以转化为后续训练数据。
- 真正的自动回复、成交归因和运营决策需要更强的数据闭环，不能在 1.0 阶段承诺。

## 3. 目标用户

- 老板：查看公司所有直播间的数据大屏、汇总数据大屏、关键经营趋势和异常提醒。
- 店长：查看直播间打法、商品讲解结构、风险话术和复盘结果。
- 运营：整理直播脚本、气氛话术、客户线索和改写建议，并对每天直播复盘进行人工打分，作为知识库优化和自动评分训练样本。
- 新人主播/场控：学习其它直播间讲解方式，模拟场控回复。
- 标注人员：对翡翠图片和截图进行属性校正、主体框标注，为模型训练准备数据。

## 4. 1.0 范围边界

### 4.1 做什么

- 直播间视频/音频采集。
- 主播语音转写。
- 直播截图、OCR、画面证据沉淀。
- 翡翠颜色、种水、样式、题材等属性识别与人工校正。
- 其它直播间监控数据挖掘。
- 虚拟场控回复和运营建议生成。
- 直播间知识库提示卡片。
- 录屏留档。
- 观察/复盘报告生成。
- 标注工作台和训练样本沉淀。

### 4.2 不做什么

- 不自动向直播平台发送评论或私信。
- 不自动下单、改价、发券、操作后台。
- 不承诺 1.0 已完成高精度翡翠专有视觉模型。
- 不承诺 1.0 已完成可直接商业化的翡翠知识库。
- 不承诺 1.0 已验证成交提升、气氛提升或运营 ROI。

## 6. 总体解决方案

### 6.1 方案概览

```text
手机直播画面
  -> HDMI 采集卡或 scrcpy 投屏
  -> JLAO 后端采集视频/音频
  -> 前端实时预览
  -> STT / OCR / YOLO / 截图 / 录屏
  -> 商品属性、话术、客户线索、风险点、虚拟回复
  -> 商品库、知识库、截图证据、复盘报告、训练样本
```

### 6.2 采集链路

1. HDMI 采集卡模式  
   当前 iPhone 方案推荐使用：iPhone -> Lightning 转 HDMI -> HDMI 采集卡 -> USB3.0 -> PC。后端统一打开采集卡视频和音频设备，前端显示后端 MJPEG 预览流。

2. Android / scrcpy 兼容模式  
   保留 Android 手机投屏、ADB、scrcpy 启动和浏览器接入视频流能力，用于兼容历史调试环境。

3. 资源状态模型  
   系统将采集、视频流、音频接入、语音识别、截图/OCR、录屏拆成独立资源，分别启动、停止、报错和复位，避免一个按钮隐式开启全部功能。

### 6.3 数据处理链路

```text
视频帧
  -> 实时预览
  -> 截图卡片
  -> OCR 文本
  -> YOLO 主体检测
  -> 翡翠属性推断
  -> 人工校正与训练样本

音频流
  -> 阿里云 STT 或本地 FunASR
  -> 主播话术转写
  -> 商品描述、风险话术、运营建议

弹幕/互动线索
  -> 客户线索
  -> 用户问题归类
  -> 虚拟场控回复

视频 + 音频
  -> 录屏临时文件
  -> FFmpeg 合成 MP4
```

### 6.4 识别策略

1. 文本优先  
   主播语音和 OCR 文本用于抽取颜色、种水、样式、题材、尺寸、价格、证书和瑕疵。

2. 视觉辅助  
   OpenCV 用于颜色、亮度、清晰度、种水启发式判断；YOLO 用于主体区域和样式/题材检测；VLM 用于补充语义判断。

3. 人工校正闭环  
   识别结果允许人工校正，校正结果进入反馈池和标注任务，用于后续专有模型训练。

## 7. 已完成功能

已完成前后端基础框架：

- FastAPI 后端服务。
- Vue 3 + TypeScript 前端看板。
- JWT 登录鉴权。
- 前端路由和页面骨架。
- Pinia 全局状态管理。
- WebSocket 实时状态推送。
- 会话、商品、转写、截图、建议、客户线索、Agent、复盘等基础数据模型。
- SQLAlchemy 数据持久层。
- 上传文件和录屏文件的受控访问。
- 前端生产构建由后端静态托管。
- 测试用例覆盖部分核心服务、采集状态、观察页结构和翡翠识别合同。

### 7.2 采集控制与硬件接入

已完成：

- 输入模式支持：HDMI 采集卡 / scrcpy。
- 采集卡视频设备枚举和启动。
- 采集卡 MJPEG 实时预览。
- 采集卡画面 180 度旋转、左右镜像、画面填充模式。
- 采集卡黑屏/无信号状态提示。
- 采集卡预览 FPS 显示。
- 采集卡音频接入。
- Android scrcpy 投屏兼容链路。
- 采集、接入视频流、音频接入、语音识别、截图/OCR、录屏六类独立开关。
- 前端按钮按下锁定/再次点击释放的视觉状态。
- 软重置/硬重置资源状态设计。

### 7.3 语音识别

已完成：

- 原生音频接入，不使用电脑麦克风。
- STT provider 支持本地 FunASR 和阿里云。
- 设置页可切换本地 CPU/GPU 与 STT provider。
- 当前策略支持在 OCR 开启时使用阿里云 STT，降低本地 OCR 和本地 ASR 资源互相干扰。
- 实时转写面板展示主播语音。
- 语音流断开时可停止 STT，并同步状态。

### 7.4 截图、OCR 与视频分析

已完成：

- 截图/OCR 独立开关。
- OCR 频率配置。
- PaddleOCR 接入。
- 采集卡模式下 OCR/YOLO 使用后端最新帧缓存，减少浏览器端截图对视频流的影响。
- 截图卡片沉淀画面证据、清晰度、亮度、OCR 文本、翡翠属性和识别来源。
- 截图卡片支持属性校正。
- 画面卡死检测和异常状态提示。

### 7.5 翡翠识别与商品库

已完成：

- 翡翠多模态识别实验室。
- 支持图片 + 讲解文本批量识别。
- 识别字段：颜色、种水、样式、题材、尺寸、价格等。

- 商品库展示直播在售商品。
- 商品人工标注：颜色、种水、样式、题材。
- 反馈样本沉淀。
- 批量识别结果 CSV 导出。

### 7.6 其它直播间监控的数据挖掘

- 采集其它直播间画面和声音。

### 7.8 录屏

## 8. 未完成与下一阶段要完成的功能

### 8.1 翡翠图像识别优化 / 专有模型优化

当前状态：

- 已有 OpenCV、YOLO、VLM 可选能力。
- 已有少量训练样本、测试脚本和标注工作台。
- 当前模型仍属于 MVP/实验阶段，不能作为高准确率商业识别模型。

下一步：

- 需要 5000 到 10000 张真实翡翠图片做人工标注。
- 标注内容包括主体框、颜色、种水、样式、题材、瑕疵、证书/尺寸/价格等。
- 建立训练集、验证集、困难样本集和回归测试集。
- 针对直播场景优化：强光、反光、手持晃动、低清晰度、遮挡、字幕覆盖。
- 建立模型评估指标：属性准确率、主体检测召回率、误识别率、低置信度召回策略。

### 8.2 翡翠专有知识库搭建

当前状态：

- 已有通用直播间知识提示卡片。
- 已有 wiki/知识库命中模块。
- 当前内容主要是静态规则、识别属性和通用话术，不是完整专有知识库。

下一步：

- 需要直播间后台数据支持，包括商品后台、历史成交、讲解脚本、客户问题、售后反馈、证书资料。
- 每天货盘图片放在固定位置，例如本地目录、共享盘或对象存储路径；知识库按固定时间读取该位置的新图片，自动建立当日货盘草稿。
- 货盘图片读取后，需要识别图片中的货品、编号、价格带、证书信息、瑕疵提示和主推顺序，并和商品库、历史成交、粉丝画像、购买画像做关联。
- 对低置信度、重复图片、缺少编号、价格不清晰、证书缺失的货品生成待确认清单，由运营在开播前确认，不能让系统直接把不确定识别结果当成正式货盘。
- 建立翡翠知识结构：颜色、种水、场口、工艺、题材、瑕疵、证书、价格带、适合人群、禁忌话术。
- 建立可检索知识库和引用来源。
- 将知识库和当前商品、客户问题、主播话术、风险规则实时联动。
- 输出可追溯话术，不只生成泛化文案。
- 将运营每日复盘打分、优秀/较差话术、成交节点、冷场节点、风险改写结果沉淀为知识库训练样本，让知识库从“提供资料”逐步进化到“参与评价”。
- 知识库进化后，需要能够根据每天确定的货盘、粉丝画像、购买画像，为主播和运营输出货品讲解建议、开播前预训练内容、开播建议和开播计划；直播过程中再根据主播状态、在线人数、互动热度、成交/加购/询价情况动态调整讲解顺序、气氛话术、逼单节奏和风险提醒。

### 8.3 翡翠运营 / 气氛脚本策划

当前状态：

- 已有虚拟场控回复流。
- 已有运营建议、风险改写、主播补充话术。
- 已有直播间知识库提示卡。
- 但这些内容还没有经过真实直播演练验证。

下一步：

- 开播前：根据当天确定的货盘，结合粉丝画像、购买画像、历史成交和运营目标，生成主播预训练材料、货品讲解顺序、重点卖点、禁忌话术、福利节奏和开播计划。
- 开播前固定流程：运营上传或放置当日货盘图片；系统定时读取并生成货盘解析；运营确认后，知识库输出当日主推款、引流款、利润款、福利款、压轴款建议，以及每件货适合讲的卖点、适合人群、风险提醒和备选话术。
- 直播中：根据主播状态、在线人数、弹幕互动、询价、加购、成交和冷场情况，实时给运营和主播调整建议，例如换货顺序、补讲证书/瑕疵、加强留人、降低风险话术、调整逼单节奏。
- 直播中如果某件货互动差、停留低或询价少，系统需要建议提前换款、换讲法、补讲场景价值或切到福利款；如果某类货成交好，需要建议延长同类款讲解或把相似款提前。
- 需要进行实战演习，验证脚本是否自然、是否适合主播风格、是否能带动停留和互动。
- 建立脚本类型：开场、留人、逼单、转款、福利、节奏拉升、冷场救场、风险降级。
- 建立话术分级：可直接说、需主播确认、仅运营参考、禁止使用。
- 建立主播反馈机制，把好用/不好用脚本回写系统。

### 8.4 数据大复盘优化

当前状态：

- 已有复盘报告和观察报告骨架。
- 已能汇总话术、风险、问题、建议。
- 但报告仍偏通用，需要运营视角进一步定义指标。

下一步：

- 需要运营给出复盘维度和评价标准。
- 每天直播结束后，由运营对本场复盘进行人工打分，评分维度包括讲品完整度、节奏、互动、逼单、风险控制、成交承接、气氛和复盘可执行性。
- 运营打分必须沉淀为结构化数据，反哺知识库和复盘规则；早期由运营打分，中期由系统给出建议分，后期目标是由知识库基于历史评分标准自动打分。
- 增加关键指标：讲品数量、每件货讲解完整度、互动密度、风险话术次数、成交卡片命中、停留节点、节奏断点。
- 支持按场次、主播、商品、平台、时间段对比。
- 支持复盘结论转成训练题、脚本优化建议和下一场执行清单。

### 8.5 平台真实闭环

1.0 未完成真实平台闭环：

- 未接入视频号/抖音官方直播后台。
- 未拉取真实订单、真实用户身份、真实成交数据。
- 未自动发送评论或私信。
- 未做自动场控执行。

这些能力必须等风控、权限、审核和运营策略成熟后再进入后续版本。

## 9. 关键验收标准

### 9.1 1.0 可演示验收

- 能打开系统并登录。
- 能进入其它直播间分析页面。
- 能启动采集卡输入或 scrcpy 兼容输入。
- 能看到实时画面。
- 能接入音频并启动 STT。
- 能启动截图/OCR，产生截图卡片。
- 能识别或人工校正翡翠属性。
- 能看到直播间知识库提示。
- 能看到虚拟回复/客户线索/复盘骨架。
- 能启动和停止录屏，并生成 MP4。

### 9.2 观察数据验收

每场公开直播至少应产出：

- 5 条以上主播转写片段。
- 3 张以上截图证据。
- 1 组以上翡翠属性识别或人工校正结果。
- 3 条以上可复用话术或场控建议。
- 1 份复盘/观察报告。

### 9.3 训练样本验收

- 识别结果可保存反馈。
- 截图可进入标注工作台。
- 人工框和属性可保存。
- 可重建训练集。
- 可区分已确认、待复核、需人工框样本。

### 9.4 货盘与开播计划验收

- 支持配置每天货盘图片固定读取位置。
- 支持按固定时间扫描新增货盘图片，并生成当日货盘草稿。
- 能把货盘草稿关联到商品库、知识库、粉丝画像和购买画像。
- 能标记低置信度、重复、缺少编号、缺少价格或证书不清晰的货品，交给运营确认。
- 运营确认后，能生成主播预训练内容、开播计划、讲解顺序、主推/福利/利润/压轴款建议。
- 直播过程中能根据在线人数、互动、询价、加购、成交和主播状态，给出货品顺序和话术调整建议。

## 10. 风险与约束

1. 采集链路风险  
   HDMI 采集卡、USB、转接线、手机输出、Windows 设备占用都会影响稳定性。

2. 本地算力风险  
   OCR、YOLO、本地 FunASR、VLM 同时运行会抢 CPU/GPU，当前已通过阿里云 STT 缓解语音识别被本地 OCR 干扰的问题。

3. 图像识别准确率风险  
   直播场景中强光、反光、压缩、遮挡、主播手部遮挡会明显影响识别，需要大规模真实数据训练。

4. 知识内容风险  
   翡翠知识和价格判断必须可追溯，不能把通用 AI 文案当成专家结论。

5. 合规风险  
   系统 1.0 只做观察和模拟，不应真实发送平台互动，避免误发、刷屏或违规营销。

## 11. 版本路线

### 1.0：内部可演示版本

- 完成框架搭建。
- 完成其它直播间观察和数据挖掘基础闭环。
- 完成采集、STT、OCR、截图、识别、知识提示、虚拟回复、录屏、复盘、标注基础能力。

### 1.1：数据和模型增强版本

- 建立 5000 到 10000 张人工标注数据集。
- 优化翡翠 YOLO/属性模型。
- 完善标注质检和模型评估。
- 增强识别结果置信度和复核机制。

### 1.2：专有知识库版本

- 接入直播间后台资料。
- 建立可检索翡翠知识库。
- 将知识库、商品库、话术、客户问题联动。
- 支持固定位置定时读取每日货盘图片，生成待运营确认的当日货盘草稿。

### 1.3：运营脚本和复盘版本

- 基于实战演习优化气氛脚本。
- 与运营共同定义复盘指标。
- 输出可执行的下一场直播优化清单。
- 基于确认后的每日货盘、粉丝画像和购买画像，生成开播前训练、开播计划和直播中动态调整建议。

### 2.0：真实运营闭环版本

- 在权限、合规、审核和风控成熟后，再考虑接入真实直播后台和半自动/自动场控能力。
